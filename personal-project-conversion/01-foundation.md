# Phase 1 — Reproducible and honest foundation

**Implementation status: Complete.** Implementation, P1-01–08 acceptance, and separate evidence review passed September 6, 2026; see [Phase 1 evidence](evidence/phase-1.md). Revised September 6, 2026. See the [package index](README.md) for scope and phase order and the [shared contracts](00-shared-contracts.md) for cross-phase behavior.

## Outcome

A clean copy of the delivered repository can run the documented checks and open an application whose data origin and feature availability are clear. Real mode displays actual stored information, including honest empty/error states. The personal navigation contains Today, Saved, and Briefs.

This phase can start immediately. Personal interests and paid-provider settings are not needed for its offline implementation and checks. Saving and briefing remain visibly unavailable until Phase 2 connects them.

## Fixed behavior

| Subject | Required behavior |
| --- | --- |
| Default mode | Real mode is the default. Missing configuration or an unreachable API never selects demo mode. |
| Demo entry | A deliberate, labeled mode control opens a read-only demonstration. Demo mode uses fixtures only; it does not combine fixtures with real responses. |
| Display-mode switching | Changing between real and demo clears displayed collections, evidence, pending UI requests, and caches associated with the previous display mode. Late responses from the previous mode cannot populate the new view. This is a browser display operation; it does not change the database's processing runtime mode or cancel a real run. |
| Demo labeling | A persistent “Demo — sample data” label appears on every demo screen and evidence drawer. Its authored timestamps remain sample timestamps, not “updated now.” |
| Demo actions | Actions that would save data, collect news, invoke AI, or export a purported personal brief are disabled with an explanation. Authentic HTTP(S) source links may open normally. |
| Empty real data | An empty API response shows an empty state with the available next step. Fixture event IDs, chart points, evidence, and report text never enter the real data store. |
| Failed real request | First-load failure shows an error and retry-display control. If data already loaded in this browser session, it may remain visible with “Unable to refresh” and its actual last successful fetch time. No success toast is emitted. |
| Evidence | Display only the retained excerpt returned for that evidence record. Missing/empty excerpts show “No excerpt available.” Do not derive a quotation from the title or generate representative prose. |
| Source URL | Only an available, parseable HTTP(S) URL enables “Open original source.” Missing or invalid links show “Source link unavailable.” A clickable URL is not a claim that the publisher will permit access. |
| Freshness | Distinguish source publication time, data fetch time, and processing success time. Fetching a stored record does not make the underlying news newly collected. Missing timestamps remain unspecified. Once personal run reads are connected in Phase 2, apply the shared rule: show the latest readable stored result and a newer running/failed update separately. |
| Navigation | Today, Saved, and Briefs are the main destinations. Event detail remains reachable from Today. Settings becomes a utility destination when the relevant Phase 3 settings are implemented. |
| Deferred destinations | Forecasts, risk maps, general Ask AI, model debates, company research, external alerts, and administration prototypes are absent from personal navigation and search/command shortcuts. Direct links show “Unavailable in personal mode”; they do not silently open an unrelated page. |
| Unfinished core actions | In-scope actions stay visible only when their disabled explanation is useful, such as “Saving is unavailable in this version.” Do not simulate persistence, runs, or generated briefs. |

For existing route compatibility, map the existing events destination to Today, watchlist to Saved, and reports to Briefs; route both the old dashboard and application root to Today. Existing event-detail links continue to identify their event. Internal route naming may be retained where it avoids unnecessary changes.
