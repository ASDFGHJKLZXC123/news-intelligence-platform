## Delivered behavior

- Personal runners share a process-local LRU prompt cache capped at **256 entries, 16 MiB encoded UTF-8 key/value bytes, and one-hour TTL**. Oversize entries are skipped; cached results are decoded independently. Runner exit loses only temporary cache content.
- One local governor shares each provider's configured RPM/TPM buckets across generation, embeddings, model names, and physical retries. Buckets begin empty in every new process. Physical calls are serialized; numeric/date `Retry-After` and cancellation respect the existing persisted graceful deadline. PostgreSQL reservations and global ownership remain authoritative.
- Both supported personal delivery transports use that local assembly. The original explicitly selected legacy LLM runtime retains its Redis assembly. Personal subprocess reading/settings/raw runs/health/shutdown do not initialize Redis, Celery, or Beat.
- The personal FastAPI app serves the existing frontend and `/app` assets at the same loopback address as its API. Known direct browser routes load correctly; unknown API/asset/private paths retain JSON errors. Local same-origin mutations still require the configured API key and preserve foreign-origin/nonlocal rejection.
- `scripts/personal-local.py` runs one foreground app or explicit supervised CLI operation. It preserves an exported database/auth configuration, enforces loopback/one worker/paid activation off, never overwrites `.env`, and never migrates, switches durable mode, or starts an update implicitly. The dedicated Compose file contains only PostgreSQL on a separate default port **55443**. Existing workspace data requires explicitly selecting its database.
- Shutdown, recovery, checksummed disposable restoration, and idle-only legacy selection use the existing guarded services. No schema downgrade or new migration was required; current revision remains `0023_personal_processing_control`.
